Why local-first

Your data. Your rules.

Private

Conversations, files and memory stay on your own machines instead of someone else’s servers.

Predictable cost

Run open models locally and escalate to a cloud model only when a task earns it — no surprise per-token bills.

No lock-in

Memory and tasks live in your own database, so you can swap models and vendors without starting over.

Auditable

Every action is logged, so you can always see what an agent did, when, and why.

How it works

A manager, specialists and a gate

The AI model never has the last word. A deterministic control layer decides what’s allowed, what needs a human, and what is simply denied.

Step 1YouAsk by voice or text, from your desk or your cab.
Step 2Local manager modelUnderstands the request, plans the work and decides who should do it.
Step 3 · The control layerPermissions & approvals Plain, predictable rules — not an AI guess — check every action before it happens.
Allow — safe, sandboxed workAsk a human — pushes, spending, messagesDeny — anything unknown
Step 4Specialist modelsCoding, reasoning and research, each handled by the model best suited to it.
Step 4Sandboxed toolsFiles, code and web access inside fenced-off folders, never the whole machine.
Always onLong-term memoryA local database that remembers tasks, decisions and context across sessions.

What’s working today

Working prototypes running on real hardware — not yet packaged products.

Manager + specialists

Working prototype

A local manager model breaks requests into tasks and hands them to specialist models for coding, reasoning and research, then pulls the results back together.

Shared long-term memory

Working prototype

Conversations, tasks and decisions are stored in a local database that any approved tool can read — so context follows you between apps and models.

Hands-free voice

Working prototype

A headset-driven voice assistant that listens, thinks locally and talks back — built for use where typing isn’t an option.

Sandboxed coding agent

Working prototype

Writes code, runs tests, repairs failures and commits to a feature branch — then stops. Pushing or merging requires a human yes.

Self-maintaining memory

Working prototype

Background agents keep memory in step with your chats and coding sessions, verify their own work, and report whether their last run succeeded or failed.

Ground rules

How every agent is built

  • Local firstRun on your own hardware by default; reach for the cloud only when it’s worth it.
  • Human in the loopPublishing, spending money, sending messages and changing networks always need a person’s approval.
  • Fail closedIf an action isn’t explicitly allowed, it’s denied.
  • Test before trustGenerated code is checked and tested before it’s accepted — the model’s confidence isn’t proof.
  • Audit everythingEvery action leaves a record you can read later.
